# Out of scope

Generated by `tools/gen-settings-ledger.py` from the table the settings
surface carries as `capabilities`. Do not edit by hand.

6 features the reference slicers ship and this engine will not build.
Each one is a project in its own right, not a setting; the cost of saying so
is a control the panel shows as unavailable, and the cost of not saying so is
a decade of work that ends in a worse copy of PrusaSlicer.

| feature | what the engine does instead |
| --- | --- |
| **Text embossing and font loading**<br>A mesh with the text already in it is an ordinary object; the engine reads no fonts and places no glyphs. | any STL, 3MF or OBJ that carries the embossing |
| **Cut and hollow**<br>The engine slices a closed mesh; it never subtracts, splits or shells one. A cut or hollowed body has to arrive that way. | a mesh prepared in CAD |
| **STEP and IGES import**<br>B-rep to triangle needs an OCCT-class kernel, which is a dependency this project will not take. Nothing here reads a parametric solid. | STL, 3MF or OBJ |
| **Resin (SLA/DLP) slicing**<br>The pipeline is filament: extrusion per bead, retraction, a layer cooling rule. Resin wants exposure per layer and no extrusion. | nothing — it is not a filament process |
| **Multi-material colour mixing (MMU, AMS)**<br>A tool changer is in scope and a colour mixer is not: beads are assigned to tools, never blended within one layer. | Tool settings and toolchange_gcode |
| **Nesting arranger**<br>The arranger is a shelf packer: it fills rows, it does not interlock irregular outlines. It falls back to turning a part a quarter turn. | hfw_plate_arrange |

The application reads the same rows from `hfw_settings_surface_json`: every
entry has `id`, `title`, `disposition` (`out_of_scope`), `panel`
(`unavailable`), `note` and `instead`. A panel that renders an unavailable
control from that list cannot drift from this document, and adding a feature
here means changing one table.

What is *not* on this list matters as much: every setting the engine parses
and reads is in `SETTINGS-LEDGER.md` with the command that measured it, and
every setting it does not apply is `missing` or `partial` there rather than
silently ignored.
